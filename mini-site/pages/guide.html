cd agora

Adding a new API contract to the catalog

  1. Create a new folder under apis/, e.g. apis/my-new-api/.
  2. Add openapi.yaml. If it needs shared schemas, $ref them against the governance server: 
    $ref: 'http://localhost:8081/shared-models.yaml#/components/schemas/Customer'
  3. Add catalog-info.yaml modeled on apis/sample-orders-api/catalog-info.yaml (kind: API, spec.type: openapi, spec.definition using $text: ./openapi.yaml).
  4. Register the new location in backstage/app-config.local.yaml under catalog.locations as a type: url entry — not type: file (see gotchas below).
  5. Restart Backstage: docker compose restart backstage.
  6. Verify at http://localhost:7007/api/catalog/entities and the catalog UI.

Troubleshooting

curl/browser hangs on localhost: you're behind a corporate proxy. Use curl.exe --noproxy '*' <url> instead of PowerShell's Invoke-WebRequest.

New/edited API doesn't appear in the catalog: check docker compose logs backstage. The most common cause is a catalog.locations entry using type: file with an absolute path — Backstage's $text placeholder resolver needs a URL-schemed base to resolve the relative ./openapi.yaml ref. Switch to type: url instead.

File rename/move fails with "in use" on Windows: Docker Desktop can hold file locks on bind-mounted directories even after docker compose down appears to finish. Retry the down, or use robocopy /MOVE instead of Rename-Item/Move-Item.
